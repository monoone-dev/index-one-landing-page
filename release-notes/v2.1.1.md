*Originally released on 2026-08-29.*

A fix release for 2.1.0's Space sharing, found on the first real two-account test.

## A shared Space now actually appears as a Space

The org feed has two ingest paths — the live pull that runs on every sync, and
an anti-entropy sweep that only runs when the live pull found nothing. 2.1.0
taught the sweep about shared containers and missed the live pull, which is the
one a healthy app actually uses.

So a shared Space arrived as an ordinary **note named after the folder**, sitting
in Shared Ivys instead of appearing in the sidebar. The same gap meant a
document's placement was never recorded, so even a correctly received container
would have been empty.

**Existing installs heal themselves.** Manifests that were stored as notes are
moved to where they belong on first launch. The old row is tombstoned rather than
deleted, so a later replay of the same feed item cannot resurrect it, and a row
that will not parse is left untouched.

## The shared marker reaches single items

2.1.0 marked shared Spaces and folders but not individual items. Now a note
someone shared with you says who shared it and at what access, and a note *you*
published on its own says where it went — so you can tell from your own sidebar
that it left for an organisation.

An item inside a shared container stays unmarked on purpose: its container's row
already says it.
